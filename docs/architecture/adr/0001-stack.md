# ADR 0001: Technology stack

- Status: Accepted
- Date: 2026-10-12

## Context

Paraphe tracks the approval of construction execution documents. The product
lives or dies on traceability: who opened what, who gave which opinion on which
revision, and when. The domain has real business rules (an opinion belongs to a
revision, the global status is derived, the event log is append-only) and must be
testable without infrastructure.

The team is one developer plus a domain expert. The code must reach a
professional quality bar without operational complexity the team cannot carry.

## Decision

| Concern | Choice |
|---|---|
| Language | Java 25 (LTS) |
| Framework | Spring Boot 4.1.x |
| Build | Maven, through the Maven wrapper |
| Database | PostgreSQL |
| Migrations | Flyway |
| Persistence | Spring Data JPA for aggregates; explicit SQL for the event log |
| Security | Spring Security, server-side sessions for the contractor; hashed random tokens for reviewer links |
| API contract | OpenAPI generated from code |
| Tests | JUnit 5, Testcontainers (real PostgreSQL) |
| Style | Modular monolith, hexagonal where there are real rules, plain CRUD elsewhere |

Module boundaries (projects, documents, reviews, audit, identity) are verified by
an automated test, not by convention.

## Alternatives considered

- **C# / ASP.NET Core**: equally capable for this domain. Not retained in favor
  of the Java/Spring ecosystem, which is widely adopted in enterprise
  environments.
- **TypeScript / NestJS**: would share types with the frontend. Not retained
  because the domain core benefits from a strongly typed, mature ecosystem with
  first-class tooling for architecture tests.
- **Microservices**: complexity without benefit at this scale. A modular
  monolith keeps the option of extracting a module later.
- **jOOQ instead of JPA**: attractive for the follow-up dashboard queries.
  Deferred, not rejected; it can coexist with JPA.

## Consequences

- The event log is written with explicit SQL so that "never UPDATE or DELETE" can
  be enforced and tested at the database level, without an ORM tracking changes.
- The domain stays plain Java with no framework dependency, which keeps business
  rules fast to test.
- `jOOQ` is to be re-evaluated if the follow-up dashboard queries become hard to
  express in JPA.
- Reviewer accounts are out of scope for MVP 1, but the model must not prevent
  adding them later.
- Spring Modulith and Docker Compose support are not yet in the `pom.xml` and
  will be added when the modules and the local database are set up.
- Versions are those generated by the project initializer on 2026-10-12 (Spring
  Boot 4.1.1, Java 25); upgrade within the same major as needed.
